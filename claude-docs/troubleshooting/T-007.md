# T-007 · 같은 사이트라도 피드와 원문 페이지가 요구하는 UA 가 다르다

- **증상**: og:image 백필을 실측하려고 만든 스크립트에서 한국경제(`https://www.hankyung.com/feed/economy`)만 `invalid XML: Tag '=' is an invalid name.` 로 죽었다. 같은 스크립트에서 연합뉴스·BBC·Ars·ZDNet 은 전부 정상이라 "우리 파서가 이 피드만 못 읽나" 로 보였다.

- **원인**: 파서가 아니라 **받아 온 것이 XML 이 아니었다.** 스크립트가 모든 요청에 브라우저형 UA 를 썼는데, 한국경제 피드는 그 UA 에 Cloudflare 챌린지 페이지를 돌려준다. UA 를 바꿔 가며 실측:

  ```
  브라우저 UA  → <!DOCTYPE html>…<title>Just a moment...</title>   (Cloudflare 챌린지)
  collect UA   → <?xml version="1.0" encoding="UTF-8"?><rss …>      (정상 피드)
  ```

  방향이 직관과 반대다 — 보통은 커스텀 UA 가 막히고 브라우저 UA 가 통한다. 원문 **기사 페이지**는 반대로 양쪽 UA 모두 통과한다(같은 스크립트로 확인).

- **해결**: 프로덕션 코드는 원래부터 UA 를 갈라 쓰고 있어 손댈 것이 없었다 — 피드 fetch 는 `morning-brief/1.0 (+…)`, 원문 og 백필만 브라우저형 UA. 고장 난 것은 실측 스크립트 쪽이었다. 고치고 다시 재니 한국경제 RSS 이미지 0/50 → og 백필로 기사 사진 3건 통과·로고 2건 차단으로, 설계가 예상한 3:2 분포가 그대로 나왔다.

- **재발방지**: **"파싱 실패" 는 파서를 의심하기 전에 받아 온 바이트를 먼저 찍는다.** 응답 앞 300자만 봐도 XML 인지 챌린지 HTML 인지 즉시 갈린다. 그리고 **collect 의 피드 UA 를 브라우저형으로 "통일"하지 말 것** — 한국경제 피드가 조용히 챌린지 HTML 로 바뀌고, 파싱 예외가 소스 단위 `try/catch` 에 먹혀 그 소스만 매일 0건이 된다(같은 계열의 무성 실패는 [T-003](T-003.md)). 두 UA 가 다른 것은 실수가 아니라 실측 결과다.
