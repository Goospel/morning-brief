# T-001 · GitHub 레포명 한글은 무성 치환된다

- **증상**: `gh api user/repos --input`에 `{"name":"나만의정보","private":false}`를 넣어 공개 레포를 만들었더니 실제로는 `Goospel/-`가 생성됐다. 한글 5글자가 전부 `-`로 바뀐 뒤 연속 하이픈이 하나로 접혀 이름이 `-` 한 글자가 됐다. **에러도 경고도 없었고 HTTP 201 성공이었다** — 응답의 `.name`을 눈으로 보고서야 알았다.

- **원인**: GitHub 레포 이름은 ASCII 영숫자와 `-` `_` `.`만 허용한다. 그 밖의 문자는 **거부가 아니라 `-`로 치환**된다. 요청 자체는 정상 성공이라 종료 코드·에러 메시지·`set -e` 어디에도 걸리지 않는다. 반면 `description` 필드는 유니코드를 그대로 받으므로, 한글이 통과하는 필드와 죽는 필드가 한 요청 안에 섞여 있어 더 헷갈린다.

- **해결**: 잘못 생성된 레포를 지우고 ASCII 이름으로 다시 만든다. 한글 정체성은 `description`에 둔다.
  ```
  gh repo delete <owner>/<잘못된이름> --yes
  gh api user/repos --input repo.json   # name 은 ASCII, description 에 한글
  ```
  생성 직후 반드시 대조한다:
  ```
  gh api user/repos --input repo.json --jq '.name'
  ```

- **재발방지**: 한글 폴더명을 레포명으로 그대로 넘기지 않는다. 그리고 **생성 API의 성공 응답을 이름이 보존됐다는 증거로 쓰지 않는다** — 요청값과 응답의 `.name`을 명시적으로 대조한다. 이 함정은 글로벌 CLAUDE.md 「Windows 셸 한글·인코딩 원칙」의 무성 실패군과 같은 성질이다(명령은 성공했는데 값만 조용히 변형됨). 다른 서비스에서 같은 계열을 한 번 더 만나면 그쪽으로 승격 후보다.
