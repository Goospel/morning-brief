# T-002 · 큰따옴표 안 백틱이 문서 내용을 지운다

- **증상**: `python -c "..."` 로 changeLog에 문단을 삽입했더니 마크다운 코드 인용이 통째로 사라졌다. `` `.ts` `` → 빈 문자열, `` `fast-xml-parser` `` → 빈 문자열. stderr에 `.ts: command not found`가 찍혔지만 **파이썬은 정상 종료해 `ok`를 출력**했고, 파일도 정상적으로 쓰였다. 성공처럼 보이는데 내용만 빠져 있었다.

- **원인**: bash는 **큰따옴표 안에서도 백틱을 명령 치환으로 해석**한다. `"...`.ts`..."` 는 `.ts`를 명령으로 실행하고 그 표준출력(빈 문자열)으로 치환한다. 실행 실패는 stderr로만 새고, 종료 코드는 파이프라인 마지막 명령(python)의 것이라 0이다. 그래서 `&&` 체인도, `set -e`도 걸리지 않는다.

- **해결**: 백틱이 든 문서 텍스트는 셸 인자로 넘기지 않는다. 셋 중 하나를 쓴다.
  1. **Write/Edit 도구로 직접 쓴다** — 셸을 안 거치므로 가장 안전하다(마크다운 문서는 기본적으로 이 방법).
  2. 굳이 셸을 써야 하면 **작은따옴표 heredoc**: `<<'EOF'` (따옴표가 있어야 치환이 꺼진다. `<<EOF` 는 치환이 살아 있다).
  3. 백슬래시 이스케이프(`` \` ``) — 개수가 많으면 실수하기 쉬워 마지막 수단.

- **재발방지**: **셸 명령에 백틱이 들어가면 멈추고 도구를 바꾼다.** 마크다운 문서에 코드 인용은 늘 들어가므로 이 조합은 계속 마주친다. 검증도 종료 코드로 하지 말고 **쓰인 파일을 눈으로 확인**한다 — 이 함정은 [T-001](T-001.md)과 같은 무성 실패군이다(명령은 성공했는데 값만 조용히 변형됨). 글로벌 CLAUDE.md 「Windows 셸 한글·인코딩 원칙」의 형제 항목이며, 한 번 더 만나면 그쪽으로 승격 후보다.
