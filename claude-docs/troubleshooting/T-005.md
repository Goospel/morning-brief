# T-005 · 좁은 뷰포트에서 TDS Selector 화살표가 줄바꿈됐다

- **증상**: 설정 화면의 「받을 시간」 행에서 `<Selector typography="t5" type="arrow">7시</Selector>`가 다음처럼 렌더됐다 — 텍스트 「7시」 아래에 화살표(⌄)가 따로 한 줄. 심사 스크린샷에 쓸 화면이라 그대로 둘 수 없었다.

  ```
  받을 시간            7시
                       ⌄
  ```

  318px 논리 폭(심사 스크린샷 규격 636×1048의 절반)에서만 나온다. 넓은 폭에서는 정상이라 처음에는 `type="arrow"`가 원래 그렇게 생긴 것(블록 화살표)인 줄 알았다.

- **원인**: 컴포넌트 버그가 아니라 **폭 부족**이다. DOM을 재 보니 `<button>`은 `display:flex; flex-wrap:nowrap`인데 그 안의 단일 `<span>`이 `height: 51px`(= 두 줄)였다. 즉 flex 컨테이너가 감싼 게 아니라 **span 내부의 인라인 콘텐츠**(텍스트 + 화살표)가 줄바꿈된 것이다.

  ```
  span rect: width 45.08, height 51   ← 두 줄
  button rect: width 49.08, height 51
  ```

  `ListRow`의 `right` 슬롯이 준 폭이 「7시 + 화살표」에 딱 몇 px 모자랐다. 「화살표가 블록 배치라 아래에 온다」는 첫 가설과 겉모습이 똑같아서 헷갈렸다 — 두 원인 모두 「텍스트 밑에 화살표」로 보인다.

- **해결**: `Selector`에 `style={{ whiteSpace: 'nowrap' }}`을 준다. 브라우저에서 먼저 `span.style.whiteSpace = 'nowrap'`을 주입해 height가 51 → 25.5로 떨어지는 것을 확인하고 소스에 반영했다.

  ```tsx
  right={<Selector typography="t5" type="arrow" style={{ whiteSpace: 'nowrap' }}>{`${me.pushHour}시`}</Selector>}
  ```

  `Selector`의 props는 `ComponentProps<typeof Paragraph.Text>`를 포함해서 `style`이 그대로 통과한다(d.ts 확인).

- **재발방지**: **레이아웃이 이상하면 「컴포넌트가 원래 그렇다」고 결론 내리기 전에 요소의 rect를 재라.** height가 line-height의 정수배로 커져 있으면 그건 배치 옵션이 아니라 **줄바꿈**이다. 눈으로는 두 원인이 구분되지 않고, 스크린샷만 봐서는 영영 알 수 없다 — 숫자가 갈라준다.

  그리고 **고칠 때는 소스를 먼저 고치지 말고 브라우저에서 스타일 한 줄을 주입해 수치가 바뀌는지 확인**한다. 안 바뀌면 가설이 틀린 것이고, 소스를 고쳐 놓고 새로고침하는 왕복보다 싸다.

  좁은 폭 특유의 문제이므로 **디자인 확인은 처음부터 스크린샷 규격(318×524)에서 한다**. 데스크톱 폭에서 훑고 마지막에 좁히면 이런 것이 마지막에 몰린다.
