# evergreen — 시의성 없는 글이 후보 창에서 살아남게 한다

> 2026-08-24 · 상태: 설계(승인 대기)
> 배경 대화: 「뉴스뿐 아니라 개인·전문가 블로그도 모으고 싶다」
> 관련: [원 설계 5·6절](2026-08-22-personal-briefing-design.md) · [plan.md](../../../plan.md)

## 1. 문제

블로그를 `sources` 에 한 줄 넣으면 파싱까지는 그냥 된다. 파이프라인이 소스 종류를 안 가린다.
**그런데 브리핑에는 거의 안 뜬다.** 원인은 둘이고, 둘 다 고쳐야 한다.

| 코드 | 값 | 블로그에 미치는 영향 |
|---|---|---|
| `deliver` 의 `CANDIDATE_WINDOW_MS` | 3일 | 주 1회 쓰는 블로그는 **7일 중 3일만 후보에 든다** |
| `scoring.ts` 의 `freshness()` | 최대 2점, 하루 1점씩 감소 | 그 3일 중에도 **이틀 지나면 0점** |

점수는 `토픽 가중치(1~3) + 신선도(0~2)` 라 신선도 2점은 토픽 매칭 하나와 맞먹는다.
하루 300건이 쏟아지는 뉴스와 같은 창·같은 감쇠로 경쟁시키면 결과는 정해져 있다.

**핵심: 후보 창을 안 고치면 신선도만 고쳐도 소용없다.** 창이 먼저 걸러내기 때문이다.

## 2. 해법과 그 이유

기사에 **`evergreen`(시의성 없음) 플래그**를 붙이고, 그 글에만 다른 창·다른 감쇠를 건다.

### 왜 `sources.kind`(뉴스/블로그) 가 아닌가

소스 단위 구분은 **틀린 축**이다. 언론사도 기획·해설 기사는 한 달 뒤에 읽어도 유효하고, 블로그도 시황 글은 하루면 낡는다. 오래 사는 성질은 **매체가 아니라 글 자체**에 있다.

부수 효과가 크다 — **이 설계는 블로그를 한 건도 안 넣어도 가치가 있다.** 지금 있는 9개 언론사의 기획 기사가 3일 창에서 조용히 죽고 있던 것을 살린다.

### 왜 추가 비용이 없는가

요약 잡이 **이미 기사 전문을 읽고 있다**(`{summary, topics}` 를 뱉는다). 여기에 필드 하나를 얹으면 **입력 토큰 증가는 0**이고 출력만 몇십 토큰 는다.

Haiku 4.5 + Batch 50% + 환율 1450 기준 — 출력 1M당 3,625원. 건당 20토큰 × 300건 × 30일 = 18만 토큰 → **월 약 700원**. 현재 월 26,100원 대비 반올림 오차다.

별도 판정 호출을 만들면 안 된다. 그건 **기사당 1회**를 유지할 때만 싸다. 사용자×기사로 곱해지는 순간(사용자 1,000명 기준) 월 100만원대가 된다.

## 3. evergreen 판정 기준

LLM 에게 「시의성이 없는가」만 물으면 애매해서 판정이 흔들린다. **한 문장 기준 + 양쪽 예시**를 프롬프트에 박는다.

> 기준: **한 달 뒤에 처음 읽어도 내용이 그대로 유효한가.**

| | 예 |
|---|---|
| `true` | 개념·원리 해설, 방법·튜토리얼, 회고·경험담, 도구 비교, 분석 프레임 |
| `false` | 사건 보도, 시황·지수, 발표·출시·인사, 실적, 특정 일자에 묶인 일정 |

**경계 사례를 프롬프트에 명시한다.** 「신제품 출시 리뷰」처럼 뉴스와 지식이 섞인 글이 판정을 흔든다 — *출시 사실이 본문의 중심이면 `false`, 써 본 경험과 평가가 중심이면 `true`* 로 가른다.

## 4. 점수·선정 변경

### 4-1. 신선도

```
EVERGREEN_FRESHNESS = 1.5   // 고정. 감쇠하지 않는다
```

서열이 이렇게 된다 — **오늘 뉴스(2.0) > evergreen(1.5) > 어제 뉴스(1.0) > 이틀+ 뉴스(0)**.

의도한 서열이다. 속보성은 여전히 뉴스가 이기고, 낡은 뉴스보다는 evergreen 이 낫다.
감쇠를 안 거는 이유는 **후보 창이 이미 상한을 주기 때문**이다. 감쇠율 파라미터를 하나 더 만들 이유가 없다.

### 4-2. 후보 창

쿼리를 **둘로 나눈다**. 하나로 30일을 긁으면 9,000건 뉴스를 받아서 대부분 버린다.

```
뉴스(evergreen 아님):  최근 3일   ← 기존 그대로
evergreen:            최근 30일
```

### 4-3. 브리핑 내 상한

```
EVERGREEN_MAX = 2   // 6칸 중 최대 2칸
```

evergreen 은 신선도가 고정이라 **여러 건이 동점**이 된다. 상한이 없으면 토픽 잘 맞는 옛날 글로 6칸이 다 차서 「오늘의 브리핑」이 한 달 전 글 묶음이 된다.

### 4-4. 보장 슬롯은 두지 않는다 — 의도적

「해외 최소 1건 보장」처럼 evergreen 도 강제 삽입할 수 있지만 **하지 않는다.**

기존 보장 코드는 자리가 없으면 `picked[picked.length - 1]` 을 **덮어쓴다**. 보장이 둘이 되면 뒤에 도는 보장이 앞 보장이 방금 넣은 항목을 밀어낼 수 있다 — 조용히 어긋나고, 입력에 따라만 재현돼 테스트로 잡기 어렵다.

`EVERGREEN_FRESHNESS = 1.5` 면 이틀 지난 뉴스를 이미 이긴다. **토픽이 맞으면 뜨고 안 맞으면 안 뜨는 것이 맞는 동작**이다 — 관심 없는 주제의 블로그를 억지로 끼워 넣을 이유가 없다.

배포 후 실측해서 그래도 안 뜨면 그때 보장을 올린다. 그 경우 **보장 슬롯을 추적해 서로 밀어내지 않게** 하는 것이 전제다.

### 4-5. 중복 제외 기간 — 놓치면 사용자가 같은 글을 반복해 받는다

현재 `DEDUPE_DAYS = 7`. evergreen 후보 창은 30일이다.
**그대로 두면 8일째에 같은 글이 다시 뽑힌다.** 한 달에 서너 번 같은 글을 받게 된다.

```
evergreen 의 중복 제외 = 후보 창과 같은 30일
```

**불변식: 중복 제외 기간 ≥ 후보 창.** 창을 늘릴 때 이 둘은 항상 같이 움직인다.

## 5. 변경 범위

| 파일 | 변경 |
|---|---|
| `migrations/0006_article_evergreen.sql` | `articles.evergreen boolean` (NULL 허용) |
| `_shared/summary.ts` | `parseSummary` 가 `evergreen` 파싱 |
| `summarize-submit/index.ts` | 시스템 프롬프트에 판정 기준·출력 필드 |
| `summarize-collect/index.ts` | `evergreen` 저장 |
| `_shared/scoring.ts` | `freshness()` 분기, `EVERGREEN_MAX` 상한 |
| `deliver/index.ts` | 쿼리 2개, 중복 제외 기간 분기 |

### 결정 사항

- **컬럼은 NULL 허용, 기본값 없음.** 기존 행은 판정된 적이 없으므로 `false` 가 아니라 「모름」이다. 코드에서 `?? false` 로 읽어 기존 동작을 그대로 유지한다.
- **인덱스 없음.** `articles` 는 30일치 9,000건 규모다. 순차 스캔이 인덱스 유지 비용보다 싸다.
- **`evergreen` 파싱 실패는 요약을 버리지 않는다.** 필드가 없거나 boolean 이 아니면 `false` 로 폴백한다 — 플래그 하나 때문에 멀쩡한 요약을 통째로 재시도 큐에 넣는 것은 손해다.

## 6. 손대지 않는 것

**「해외 최소 1건 보장」은 그대로 둔다.** 영문 블로그가 그 자리를 먹는 것은 오작동이 아니다 — 규칙의 의도는 「해외 언론사」가 아니라 「해외 소식이 점수에 밀려 사라지지 않게」다(코드 주석). 오늘 영문 뉴스가 있으면 점수로 그것이 이기고, 없을 때만 evergreen 이 들어간다.

**Atom 전문 유입도 코드를 안 고친다.** `rss.ts` 는 `summary` 가 없으면 `content` 로 폴백해 블로그 전문이 `raw_excerpt` 에 들어올 수 있다(2000자 상한). 저작권 방침 8절의 「피드가 스스로 제공한 범위」 안이라 정책 위반이 아니다. 다만 **개인 창작자는 언론사와 사정이 다르므로**, 내려 달라는 요청이 오면 `sources.enabled = false` 로 즉시 끊는다(이미 있는 기능).

## 7. 테스트 (TDD — 실패를 먼저 본다)

`scoring.ts` 는 순수 함수라 케이스를 그대로 찍을 수 있다.

- `freshness()`: evergreen 이면 경과일과 무관하게 1.5 / 아니면 기존 감쇠
- `selectBriefing()`: evergreen 후보가 5건이어도 **2건만** 들어간다
- `selectBriefing()`: evergreen 상한이 「해외 최소 1건 보장」을 깨지 않는다
- `selectBriefing()`: evergreen 0건이어도 기존 결과가 **바뀌지 않는다**(회귀 가드)
- `parseSummary()`: `evergreen` 파싱 / 필드 누락 시 `false` / boolean 아닌 값일 때 `false`

`deliver` 는 쿼리 2개 합치기와 중복 제외 30일이 대상이다.

## 8. 리스크 · 미검증

- **판정 정확도는 형식 테스트로 못 잡는다.** 테스트는 「boolean 인가」만 본다. 실제로 정치 기사의 발언 주체가 뒤집힌 채 파이프라인을 통과한 적이 있다([T-004](../../../claude-docs/troubleshooting/T-004.md)). **실제 기사 10건 이상을 눈으로 대조**하고, 특히 경계 사례(출시 리뷰·인터뷰·연말 결산)를 골라 본다.
- **프롬프트 변경이 기존 요약 품질에 영향을 줄 수 있다.** 필드 추가는 프롬프트 수정이다. evergreen 뿐 아니라 **요약문·토픽 태그도 함께 대조**한다.
- **`EVERGREEN_FRESHNESS = 1.5` 와 `EVERGREEN_MAX = 2` 는 근거 있는 추측이지 실측이 아니다.** 서열 논리로 고른 값이다. 배포 후 실제 브리핑에서 evergreen 비율을 보고 조정한다.
- **evergreen 풀이 마를 수 있다.** 30일 중복 제외를 걸면 소스가 적을 때 넣을 evergreen 이 없어진다. 그 경우 조용히 0건이 되고 브리핑은 기존과 같아진다(안전한 실패).

## 9. 이 설계에 없는 것

**블로그 소스 추가는 별도 작업이다.** evergreen 은 소스 종류와 무관하게 동작하므로 먼저 넣어도 된다.
블로그를 넣을 때는 `npm run verify-feeds` 로 **실제 파싱 건수를 먼저 확인**한다 — 한겨레가 원시 30건·파싱 0건으로 그렇게 걸러졌다([T-003](../../../claude-docs/troubleshooting/T-003.md)).
